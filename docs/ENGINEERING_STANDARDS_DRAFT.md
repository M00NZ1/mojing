# 墨境工程标准候选（待确认）

更新日期：2026-09-28

本文用于确定墨境 Web、Android 与本机后端的共同工程边界。当前是供选择的草案，不替代 `AGENTS.md`、数据保护规则或已经生效的产品契约。确认后的项目才进入正式标准；未确认的数字不应为了“统一”而批量改写现有功能。

## 建议直接采用的底线

这些规则不依赖具体页面条数，建议作为强制标准：

1. 面向用户的列表和历史记录必须有界读取；禁止 UI 直接调用无上限的全表查询。
2. 深分页使用稳定 keyset/cursor，游标包含排序字段和唯一 ID；禁止用 Offset 扫描大型历史。
3. 判断是否还有下一页时读取 `pageSize + 1`，首屏不为显示“总数”阻塞；确有价值的总数独立统计。
4. 分页必须覆盖加载、空结果、首屏失败、后续页失败、重试、结束和筛选切换；后续页失败保留已经显示的数据。
5. 切换会话、故事线、筛选或搜索词时取消旧任务，并用 revision/request ID 阻止旧结果覆盖新状态。
6. 新增、删除、编辑后只刷新受影响窗口；不得为了刷新一项操作重新读取全部历史。
7. 数据库和交换格式升级必须版本化、幂等、保留原始数据，并有旧 schema/旧样本回放。
8. 流式模型请求不设置固定总时限；保留连接、读取和空闲超时，停止时保存最新收到且可显示的正文。
9. 写操作不得静默自动重试；只有能够证明幂等的读请求或带请求编号的写入才允许有限重试。
10. 日志、测试快照、导出和 Git 不记录完整 API Key、认证头、签名密码或用户私密正文。

## D01：分页条数策略

### 方案 A：按载荷分档（推荐）

| 场景 | 建议首批/每页 | 理由 | 当前接近值 |
| --- | ---: | --- | ---: |
| 下拉选择器、模型选择、短搜索建议 | 10 | 选择目标少，首屏清晰 | Web 模型选择 10 |
| 图片卡片、长正文卡片、事件 | 20–24 | 单条渲染和内存较重 | Android 事件 24 |
| 普通文本列表、收藏、搜索命中、目录、用量记录 | 40 | 减少频繁翻页，单条较轻 | 多数 Android 列表 40 |
| 自动摘要等长文本派生资料 | 16 | 单条长且需要展开 | Android 摘要 16 |
| 聊天时间线首屏 / 单次翻页 / 内存窗口 | 80 / 40 / 200 | 首屏连续阅读，双向翻页后仍限制内存 | Android 80 / 40 / 200 |
| 后台索引、导出、无 UI 批处理 | 128–256 | 以吞吐为主，不等于 UI 页大小 | 当前 128 / 256 |

### 方案 B：所有用户列表统一 10 条

优点是规则简单、单页稳定；缺点是聊天、搜索、收藏和目录会频繁请求与点击，不适合本地数据库和长篇阅读。建议只用于选择器，不作为全局值。

### 方案 C：所有用户列表统一 20 条

比 10 条更通用，但仍无法覆盖聊天首屏和后台批处理。可以作为没有专项设计时的默认值。

**待选择：** `[ ] A 分档`　`[ ] B 全部 10`　`[ ] C 默认 20，特殊页面例外`

## D02：加载方式

- 方案 A（推荐）：本地轻量列表接近底部自动加载；模型调用、导入、昂贵统计和长正文面板使用明确按钮。
- 方案 B：所有列表都使用“加载更多”按钮，行为最可控。
- 方案 C：所有列表无限滚动，操作最少，但错误重试和位置恢复更复杂。

**待选择：** `[ ] A 混合`　`[ ] B 全按钮`　`[ ] C 全自动`

## D03：内存窗口

- 聊天消息：建议最多保留 200 条实体，双向翻页时移出远端窗口。
- 搜索命中：建议最多保留 3 页，当前为 120 条。
- 图片或长正文卡片：建议最多保留 3–5 页；需要返回旧页时重新按游标读取。
- 用户明确逐页展开的资料面板可以暂时保留已加载页，但必须测量大数据后再决定是否加上限。

**待选择：** `[ ] 采用上述上限`　`[ ] 所有列表固定最多 3 页`　`[ ] 暂不限制用户主动加载页`

## D04：总数与页码

- 推荐：首屏先显示；总数有产品价值时后台独立统计，未知时显示“已加载 N+”。
- 不建议：为每个列表首屏执行 `COUNT(*)`，或把当前页条数写成总数。

**待选择：** `[ ] 仅搜索/用量显示精确总数`　`[ ] 所有列表后台统计`　`[ ] 一律只显示已加载数`

## D05：超时

| 操作 | 建议 |
| --- | --- |
| 模型流式生成 | 无固定总时限；连接、读取、空闲分别控制 |
| 普通元数据 HTTP | 连接 15–30 秒，读取 30–60 秒 |
| 系统能力查询 | 8–10 秒，例如 TTS 音色列表 |
| 用户主动试听/预览 | 30 秒，并提供停止 |
| 本地 Room 查询 | 不设置人为超时；通过分页、索引和后台线程保证可取消 |

**待选择：** `[ ] 采用建议`　`[ ] 普通 HTTP 更激进`　`[ ] 普通 HTTP 更宽松`

## D06：重试

- 本地读取：失败后保留旧数据，显示原位重试；不循环自动重试。
- 网络只读：可选一次短退避重试；认证、限流和参数错误不自动重试。
- 创建、发送、导入和付费请求：必须先有幂等请求编号，才允许重放。
- 数据库写入：失败后由用户重试或恢复任务接管，不在未知提交状态下重复写。

**待选择：** `[ ] 网络只读自动重试 1 次`　`[ ] 全部手动重试`

## D07：导入和文件大小

- 推荐优先做流式解析、进度、取消和事务提交，而不是只依赖文件大小上限。
- 需要给出硬上限时，可选：图片 32 MiB；角色/百科 JSON 128 MiB；聊天/备份 512 MiB。
- 超过软阈值先显示预计耗时和空间，不得先清空正式数据。

**待选择：** `[ ] 采用 32/128/512 MiB`　`[ ] 仅软警告`　`[ ] 另定数值`

## D08：日志保留

- 当前会话日志单文件最多 20 MiB，轮换后最多约 40 MiB。
- 推荐保留当前文件和一个上一文件；崩溃栈、请求 ID、引擎/模型标识可记录，正文和密钥默认不记录。

**待选择：** `[ ] 20 MiB × 2`　`[ ] 10 MiB × 2`　`[ ] 只保留本次启动`

## D09：性能验收设备与目标

建议固定一台中端 Android 真机和一个桌面浏览器配置，记录数据规模、版本、命令及冷/热启动。候选目标：

- 本地列表热启动首批可交互：500 ms 内；冷启动：1.5 s 内。
- 普通翻页反馈：点击后 100 ms 内出现加载状态。
- 60 Hz 设备连续滚动不出现可感知的多帧冻结。
- 百万 Token 会话只加载窗口，不以一次性全量读取换取演示速度。

**待选择：** `[ ] 采用候选目标`　`[ ] 只记录基线，暂不设硬门槛`　`[ ] 指定其他设备/目标`

## D10：分页必测边界

建议作为分页功能的提交门槛：

- 0、1、`pageSize - 1`、`pageSize`、`pageSize + 1` 条；
- 排序字段相同但 ID 不同；
- 翻页期间新增、删除或更新一条；
- 重复点击、取消、失败后重试；
- 切换会话、故事线或筛选后旧结果晚到；
- 旧 schema 升级后完整遍历且无重复、无遗漏。

**待选择：** `[ ] 全部强制`　`[ ] 数据/状态层强制，UI 按风险选择`

## D11：发布门槛

- 每个提交只包含一个逻辑变更，暂存 allowlist 后复核 diff。
- P0/P1 修复至少包含根因证据、定向测试、可安装构建或明确的未构建原因。
- APK 核对包名、版本、ABI、签名证书和 SHA-256；签名必须与上一安装包兼容。
- GitHub push 后核对远端 SHA 与 CI；CI 仍运行时明确写“进行中”。
- 构建、模拟器和真机结论分开报告。

**待选择：** `[ ] 采用全部`　`[ ] 仅发布版本强制 APK 核对`

## 建议的第一版

若不追求所有页面数字完全一致，建议第一版采用：D01-A、D02-A、D03-上述上限、D04-仅搜索/用量精确总数、D05-建议值、D06-网络只读一次、D07-软警告优先、D08-20 MiB × 2、D09-先记录基线、D10-数据/状态层强制、D11-全部。

确认后应把选中的规则压缩成正式 `ENGINEERING_STANDARDS.md`，并逐项审计现有实现；审计发现只进入待办，不批量改动或迁移用户数据。
