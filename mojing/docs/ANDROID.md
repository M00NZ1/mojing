# Android 开发指南

墨境 Android 使用 Kotlin、Jetpack Compose、Room、Hilt 与 OkHttp。应用入口、界面、模型请求和本地数据管理均位于原生工程。

## 界面组件

`ui/theme/Theme.kt` 统一八套主题的语义颜色、表面层级和圆角，`Type.kt` 维护标题、正文和标签排版。表单使用 `ui/common/MoJingControls.kt` 的输入框与按钮；组件保留原有键盘、焦点、错误、禁用和输入值接口，业务页面可传入必要的覆盖样式。

共用输入框采用固定上方标签、12dp 圆角与浅层描边，按主题显示聚焦、错误与禁用状态；无标签的搜索和全屏编辑保留原有尺寸约束。主要与次要按钮统一紧凑圆角和轻微按压反馈。展示标题采用衬线字形，正文保持系统阅读字体。设置折叠分组共用 `ExpandableSettingsCard`，整行标题支持展开，内容区以分隔线、统一间距和独立表面呈现。

`NavAnimations.kt` 定义前进与返回的淡入、轻位移过渡；底部导航独立处理系统导航栏与键盘边距。启动页的柔光仅作用于装饰背景，文字保持清晰。图标包含自适应前景、单色版本和各密度 PNG。

`MainActivity` 通过 `SystemBarAppearance` 统一管理状态栏与导航栏图标明暗；品牌开屏展示期间使用浅色图标，退出后按主题背景更新。开屏显示状态使用可恢复状态保存，页面重建不会重新显示已结束的开屏。

## 对话后台生成

`RetainedChatSessions` 按会话 ID 保留生成任务和 `ViewModelStore`。导航离开解除页面引用，未完成的请求与记忆整理继续运行；重新进入复用原状态，避免重复初始化和重复请求。没有页面引用且所有任务完成后释放会话窗口。取消后的持久化清理完成前继续保留任务所有权。

`GenerateService` 使用 dataSync 前台服务展示生成通知，点击通知返回对话，任务全部结束后停止服务。会话列表显示生成状态，运行中的会话需先停止生成再删除。Android 服务超时时取消任务并走既有草稿保存流程；系统终止进程后的恢复沿用已保存的回复草稿。

## 模型价格与用量

`BillingPriceRepository` 在现有 Room `app_config` 中按平台 ID 和模型名保存单价，兼容读取旧 `BillingPreferences` 配置；`ModelPricingDiscovery` 读取当前平台 `/models` 接口中的明确币种与单位。接口价格填入编辑表单后由用户保存，获取期间的手动修改保留。

`ChatEngine` 与 `LlmRetry` 在请求开始时固定平台和价格，通过流式或非流式 `usage` 记录输入、输出及缓存 Token。未返回用量时使用文本估算。每次尝试写入独立 `CostRecordEntity`，生成完成后通过 `StreamState.Done` 把本次记录附入消息结构化内容。计费记录保存失败不丢弃正文。

单价保存与历史重算在同一 Room 事务中完成。首次计价补算未计价记录；已有费用时，仅在开启“同步更新历史费用”后重算，按平台 ID 与模型名精确限定范围。免费记录也属于已计价历史。尚在生成的未计价请求入库时读取已保存单价；已固定价格的请求保留原单价。消息费用通过记录 ID、会话、平台和模型校验后读取当前费用。

`UsageViewModel` 管理平台、模型和请求三级状态，按记录 ID 倒序读取每页 40 条请求；切换层级取消旧查询并校验加载修订。`BillingCurrencyRepository` 保存显示币种和 USD/CNY 汇率，汇率刷新与手动输入使用同一状态源。

Room 20→21 为费用表增加平台、币种、用量来源、价格快照和请求状态，并增加平台/模型/记录 ID 索引。旧金额保持 USD，旧平台字段留空；迁移在 Room 升级事务内执行，失败回滚后可重试，原消息及费用记录保留。没有数据库删除或重建路径。当前源码版本为 1.1.0 / 10100。

Room 22→23 在原有角色状态表增加故事线 ID、上次提取尝试的用户消息 ID 与有效标记，并建立三字段查询索引。旧状态没有故事线归属，迁移时标为未归属且无效，完整保留原 JSON 与其他字段；新对话轮不会把它注入任何故事线。当前线有足够新用户消息时重新生成状态。消息编辑、撤回、回复版本和上下文排除沿原有事务将相关故事线快照标为无效，保留旧 JSON，清除提取游标。升级由 Room 事务执行，失败保持旧库可重试，不重建原始消息。

## 导航与界面

[NavGraph.kt](../android/app/src/main/java/com/mojing/app/ui/navigation/NavGraph.kt)管理会话列表、聊天、创作中心、角色、百科、工坊、故事推演、生成记录和设置。

顶部提供阅读模式、小说目录、会话菜单和资料入口。平台与模型位于输入框下方。会话菜单包含故事线、搜索、上下文用量、停止朗读、导入和导出。图片、语音、表情、旁白、配图及试听归入输入工具，快捷词按需展开。阅读模式收起输入区，提供继续对话与回到最新悬浮按钮。

会话资料使用可横向浏览的角色、世界、记忆、事件和书签标签。角色页的发言方式、添加入口与角色列表统一滚动；世界线路存在未保存修改时，切换资料支持继续编辑或放弃修改。

世界页优先展示玩法开关，专用线路按需展开，对话、配图与朗读配置统一保存。收起线路或调整玩法时保留线路草稿。

消息点击打开底部操作面板，长按打开文字选择页；首排提供复制、编辑和可用的重新生成；引用、收藏、朗读、续写、分支与撤回分组排列。生成期间禁用冲突操作，复制、收藏、朗读与保存图片保持可用。

收藏中的当前采用版定位到聊天历史窗口；未采用的旧回复或已不在有效故事线的原文用只读弹窗展示，提供来源提示与全文复制。查看收藏不改变故事线和回复采用状态。

收藏面板按 `(createdAt, id)` 逆序使用稳定游标，每页最多 40 条，只为已加载页读取消息预览；加载失败保留已显示收藏并提供重试。聊天消息的收藏标记按当前窗口消息 ID 查询，翻页不读取全会话收藏。收藏增删与分页刷新串行更新会话状态，不修改 Room schema。

事件面板按 `(createdAt, id)` 逆序使用稳定游标，首次读取最近 24 条，继续加载较早事件时保留已显示内容和筛选状态。仍有旧页时数量使用“+”表示已加载下限；分页失败可原位重试。Room 24 为事件表增加会话、故事线、时间和 ID 的复合索引，升级不改写事件正文。

聊天界面由消息区域、输入区和覆盖层组成。导航调整沿用现有 helper，键盘与系统栏 Insets 在对应容器处理。界面开发覆盖系统返回、输入栏可见性、弹层层级、小屏、分屏与字体缩放。

新建对话表单在页面重建后恢复用户输入，并重新读取世界和角色列表。有手动修改时关闭弹窗会先确认放弃；前往创建角色会暂存表单及创建编号，回到故事库可继续并刷新可选角色。恰好新增一位兼容角色且原先未选角色时自动选中；从工坊指定其他世界开始前确认是否替换已暂存设定。提交期间锁定表单，避免写入内容与当前显示不一致。

新建对话的角色数量、唯一候选、已选角色校验与新增角色检测由轻量 ID 查询完成，不把完整人格文本或供应商配置载入表单。角色选择器按当前世界和名称在 Room 内过滤，每页 40 条，只投影名称与排序字段；可跨页保留勾选，批量勾选明确作用于本页。查询失败保留当前选择并可原位重试。切换世界后重新校验已选 ID，创建时仍由既有事务校验实际角色资料。

新建对话只读取当前选中或默认世界的完整设定。世界选择器将百科排在未映射旧模板之前，按名称在本地查询、以稳定游标每页显示 40 个轻量选项；`custom` 占位模板不出现在列表中。点击候选后才读取完整世界，失败时保持弹窗并可重试；已删除的原选世界继续阻止按错误世界创建。旧模板到百科的映射和默认模板 ID 仍由既有数据解析，不改写世界正文。

故事库主线预览与对话窗口都按消息 ID 确定末尾，只从 Room 读取最后正文的前 1024 字；结构化回复即使在标签中途截断，也会在预览时剔除协议标签与未选择选项。完整原文仍由对话页按消息 ID 读取，列表不持有整篇章节。Room 25→26 曾为按时间查询增加 `(sessionId, branchId, createdAt, id)` 索引；现行预览读取不依赖该排序，索引与迁移保留兼容，不改写消息行。迁移失败时保留旧库，不通过删除数据恢复。

列表卡片按已保存的续聊位置展示预览：主线直接使用列表投影，非主线只对组成到屏幕的卡片读取可见末尾消息的前 1024 字。非主线读取先等待派生可见区段就绪，失败可原位重试；故事线已删除时与聊天入口一样使用主线。消息数仍仅统计主线，并在卡片标明范围。后台生成状态优先于预览，点开继续原会话而不强制切线。

故事库首次读取失败显示错误页与重试；成功显示后发生的读取错误保留现有故事列表，在顶部显示失败及重试，重试期间不清空已读取内容。只有新一轮读取成功才替换列表。

故事库每页读取 40 条卡片及 1 条后续探测记录，只计算当页消息预览、主线消息数与参与人数。排序使用 `(pinnedAt, updatedAt, id)` 降序游标，标题搜索在数据库内筛选全部本地会话；“本页”数量不是全库总数。显式上一页/下一页仅保留当前页，翻页失败保留旧页并可重试。搜索变化取消旧查询；置顶、重命名与删除改变排序后从第一页重建游标。当前分页不改变 Room schema 或会话原文。

角色主页每页读取 40 条卡片和 1 条后续探测记录，只投影展示字段、人设前 72 字及所属百科名称；推荐、最近添加和名称排序均使用对应排序字段与唯一 ID 的游标，百科筛选在数据库内执行。上一页/下一页只保留当前页；筛选、排序及置顶/收藏/删除后从首批重建游标，翻页失败保留旧页并可重试。百科筛选使用独立搜索面板，每页读取 40 个 ID、名称与游标字段，跨页保留已选百科；编辑和导出仍按需读取完整角色。生成记录按任务状态分类，展示进度、详情和结果入口。

单张角色卡导入只查询可能与新名称冲突的已有名称，不读取整库人设和供应商配置。跨设备角色导入/导出仍按百科名称解析绑定，但只读取百科 ID 与名称；完整角色内容仅在导出角色时读取。名称匹配与重名后缀规则不变。

## 平台与模型

平台配置独立保存名称、地址、Key 和模型列表，支持多个同类平台。预设为 DeepSeek、OpenAI、硅基流动、Anthropic 和自定义。

模型可通过接口获取或手动填写。聊天页以横向平台标签切换模型目录，默认定位到当前平台；点击模型后保存会话选择，从下一次发送生效。搜索图标展开为单行输入，收起后清空筛选；正在生成的回合继续使用原线路快照。默认模型选择复用紧凑搜索栏，长列表按需加载。

旧单平台配置按版本迁移到平台目录，公共文字线路与默认平台保持同步。相关实现位于 [ConfigRepository.kt](../android/app/src/main/java/com/mojing/app/data/repository/ConfigRepository.kt) 与 [SecureStorage.kt](../android/app/src/main/java/com/mojing/app/data/SecureStorage.kt)。

## 对话与记忆

[ContextBuilder.kt](../android/app/src/main/java/com/mojing/app/domain/engine/ContextBuilder.kt)负责上下文组装，[MemoryCompactor.kt](../android/app/src/main/java/com/mojing/app/domain/engine/MemoryCompactor.kt)负责自动摘要。

消息撤回在 Room 事务中检查故事线、检查点和编辑来源，计算受影响摘要并回退尾部进度。选中回复撤回时处理版本回退，历史窗口定位到附近消息。

自动摘要使用有界快照；模型返回后重新核对故事线修订、前段摘要和有效原文，再保存分段。自动事件批量核对来源、去重并提交，时间线按当前故事线刷新。

切换与重生成回复在同一事务中回退分段摘要，起点取新旧采用消息中较早的位置。重复选择保持原进度。继承摘要按编辑来源和分支回复选择过滤，保留较早有效摘要；消息刷新同步更新记忆面板。

消息操作中的上下文排除独立于回复采用版本，按当前故事线与消息/回复组存储。排除只影响后续模型历史、自动摘要及自动事件来源，原文、搜索、小说目录和章节编号继续可读。排除或恢复在同一事务中更新状态、回退摘要尾部并使通用记忆失效；回复版本切换不改排除状态。Room 21→22 仅新建 `branch_context_exclusions` 表，旧消息与采用状态不迁移或改写。

长消息由 `MemoryCompactionInput` 按保守字符权重分段，原文预算为 4,000，承接摘要预算为 2,400；ASCII 字符权重为 1，其余 UTF-16 单元为 2。分段保留消息编号、发言类型与接续标记，保持 Unicode 代理对完整。正文处理在后台调度器执行，每轮回复前或手动继续时最多调用模型整理 4 段。非末段结果把下一段位置和承接摘要写入现有 `app_config`；下次读取前用会话、故事线、修订号、来源字段、前段摘要与切段版本的指纹核对，不符则从原文重算。全部完成后复核来源、提交正式摘要并在同一事务清理检查点；会话删除同时清理派生检查点。无需 Room schema 迁移。输入区显示自动整理段数；记忆面板可手动继续、查看当前段数并停止。切换故事线或改动原文会取消手动整理；取消后可从有效检查点续跑，未完成的检查点暂不成为正式摘要。

生成任务将内容与进度同步保存。暂停在当前步骤完成后生效，任务状态持久化，续跑读取保存的进度。

自动百科整理由 `SedimentEngine` 提取条目，`SedimentStore` 管理来源快照与事务提交。快照包含百科、会话、故事线、修订和最多十条来源消息；提交时复核有效原文、修订、百科关联与自动整理开关。整批条目通过格式检查后写入，使用 `inferred` 标记，并在 `metaJson` 中记录来源消息和故事线。相同快照下标题与正文一致的内容去重；角色设定由显式编辑流程保存。

## 本地数据与资料交换

`SaveCharacterEntryUseCase` 根据数据库中的来源与角色关联处理编辑保存。带会话来源且未关联角色的条目独立保存，确认状态与扩展资料编辑沿用这一身份；已有角色镜像继续通过关联 ID 同步。编辑页由持久化条目生成“对话资料”提示。

条目编辑通过 `saveEdited` 在同一 Room 事务中读取旧正文、分配版本号、保存历史快照并更新条目。未变更内容不新增版本，保存失败整体回滚，已删除条目拒绝旧页面提交。

版本页按递增记录 ID 倒序进行游标查询，每次读取十一条判断下一页，保留十条作为当前窗口。翻页替换窗口并重置阅读位置，保存完成后显示最新版本。

[AppDatabase.kt](../android/app/src/main/java/com/mojing/app/data/local/AppDatabase.kt)维护 Room schema 与 migration。媒体使用应用文件或授权 URI，平台凭据由 SecureStorage 管理。

初始资料从 [seed_data.json](../android/app/src/main/res/raw/seed_data.json)读取，与[内置目录](../data/builtin_pack/starter_catalog.json)对应。目录包含“雾港来信”百科、世界和两名角色，初始化记录使用 `builtin_catalog_v2`。

角色 PNG 解析使用 [CharacterCardPngCodec.kt](../android/app/src/main/java/com/mojing/app/domain/util/CharacterCardPngCodec.kt)，WorldInfo 和聊天记录分别由领域解析器处理。格式说明见[角色卡与聊天记录兼容](酒馆生态与角色卡兼容调研.md)。

从不同应用标识的早期版本迁移时，通过旧应用导出、墨境导入完成数据转移。

## 开发检查

JVM 测试位于 `app/src/test/`，Room 与 Compose 测试位于 `app/src/androidTest/`。连接设备后可运行 `connectedDebugAndroidTest`。

数据变更覆盖旧 schema 迁移、事务回滚和恢复；交互变更覆盖键盘、返回、旋转、文件选择与权限。完整命令见[构建与维护](MAINTENANCE.md)。

### 角色编辑草稿

角色编辑使用独立的 `character_edit_drafts_v1` 本机偏好，按已有角色 ID 保存完整未提交表单。暂存写入在后台提交，失败保留页面输入并提供重试；重新进入时先显示正式角色资料，再由用户选择恢复或丢弃。读不出的草稿保留原始记录，明确丢弃后才允许覆盖。正式保存成功且没有期间新修改时清理草稿；清理失败留在编辑页，放弃修改也先清理后离开。无需 Room 迁移，角色正式数据与媒体文件不被草稿操作修改。

### 百科词条编辑草稿

已有词条使用独立的 `entry_edit_drafts_v1` 本机偏好，按百科 ID 与条目 ID 暂存标题、摘要、正文、标签、扩展资料和封面路径等未提交表单。读取草稿期间锁定输入，重新进入后由用户恢复或丢弃；损坏或未知版本保留原记录并要求明确选择。保存成功后按最新编辑状态更新或清理草稿，失败原位重试；放弃修改和跳转模型设置先清除草稿。新建条目正常流程先创建记录再进入编辑页；无记录 ID 的直接编辑路由不创建持久草稿。无需 Room 迁移，正式条目、版本与媒体文件不由草稿操作修改。

### 对话创作草稿

旁白方向由 ChatViewModel 管理，随会话草稿存入现有 `chat_drafts_v1`。JSON 使用可选字段 `narratorGuidance` 和配图描述 `imagePrompt`，旧记录缺失时读取为空；消息正文、附件和提交标记保持原有语义。方向写入对话成功后清空对应草稿，期间改写通过修订号保留。

配图描述使用独立修订号，沿用同一草稿存储。生成请求被接受后关闭面板，图片和附件记录写入成功后清空对应描述；失败与取消保留描述。旧记录缺失该字段时读取为空，Room schema 保持不变。

### 引用草稿

`ChatDraftStore` 在 v1 草稿中保存可选的 `quotedMessageId`，旧草稿缺省为空。会话初始化按消息 ID 与会话 ID 读取原文，原文不存在时移除引用并保留输入。发送交接标记已提交时同时清除文字与引用；恢复读取和发送完成使用引用修订号保护期间的新选择。此扩展不修改 Room schema，旧版本可忽略新增字段读取其他草稿内容。

## 小说开篇与记忆请求

`CreateSessionUseCase.create(initialMessages)` 通过 `SessionCreationTransaction` 在同一 Room 事务中写入会话、世界配置、角色与开篇消息。任一写入失败均回滚；消息继续使用现有 DAO 更新检索字段。

普通新建对话使用随表单恢复的创建编号。事务内先按编号核对既有会话，再写入新会话；重复提交返回原 ID，不覆盖其标题、世界或角色。Room 25 为旧会话默认空的编号增加唯一索引，24→25 升级不改写原会话；插入冲突中止而非替换，避免旧故事级联删除。升级失败由 Room 事务回滚，回退到旧应用版本须恢复升级前的数据库备份。

`StoryOpeningDraftStore` 在现有 `app_config` 中使用独立键 `story_opening_draft_v1` 保存版本化开篇快照，包含正文、玩法、选定角色 ID 与完整 UUID。Room schema 保持 19；旧版本无此记录时正常进入创作表单。草稿随现有数据库备份恢复，不改变 Web 交换格式。

`SessionCreationTransaction` 核对 UUID，在会话与全部章节提交时将 pending 草稿更新为 saved 回执。重复保存复用会话 ID；待保存正文和完成回执分别按状态清除，旧页面不能重新写入已交接的草稿。`StorySimulationViewModel` 重进后读取草稿或回执，提供复制全文、继续保存、打开会话和开始新作。数据库读写与恢复解析在后台执行。

不支持的草稿版本或损坏内容保留原始记录，界面支持重新读取、复制恢复数据与确认清除。磁盘写入失败时保留页面内完整正文；章节或回执写入失败时整个会话事务回滚。恢复测试覆盖真实文件数据库关闭重开、故障注入、旧 UUID、回执清除，以及测试进程结束后的页面恢复。

`StorySimulationViewModel.inputRevision` 只随用户实际修改的文本、章节数量与选择递增。请求结果及错误以提交时的输入修订判断归属；资料列表的异步刷新和自动过滤不改变修订。生成与保存均复用提交时的世界、百科和角色快照。

小说开篇通过 `LlmRetry.chatCompletionStreamingWithRetry` 消费流式正文，保留完成协议校验、取消传播与有界重试。请求总时限为 5 分钟，OpenAI 兼容线路读取空闲上限为 90 秒；收到正文后不自动重发。`StoryStreamingPreviewParser` 增量提取章节内容，界面保留最近 12,000 字符的预览。

通用记忆使用明确的对象和数组结构，解析时校验嵌套字段类型。文本字段收到字符串数组时逐项换行保留，事实列表收到单个字符串时转换为单项列表；对象、数字和空值不作为文本事实接收。自动失败按会话、故事线和请求线路短暂冷却；重建与清空会重置冷却，过期修订不推进来源位置。

开篇和通用记忆为独立的结构化输出任务。已适配的 DeepSeek 混合模型使用 `response_format: json_object`，官方接口附加 `thinking.type: disabled`，硅基流动附加 `enable_thinking: false`；普通聊天沿用原有模型参数。记忆输出预算为 3,200 Token，提示词按字段压缩和去重；接口返回 `finish_reason: length` 时按输出不完整处理。参数定义见 [DeepSeek](https://api-docs.deepseek.com/guides/thinking_mode/) 与[硅基流动](https://docs.siliconflow.cn/docs/api/chat-completions-post)。

`RealProviderStoryTest` 提供显式启用的真实平台验收，使用独立 Room 数据库与偏好存储。临时 Key 从测试应用私有文件读取，测试参数仅传入 `realProviders=true`；正常测试和 CI 不会调用付费接口。覆盖单章、双章、记忆重建与清空、生成前后取消、无效模型修正后重试。测试完成后删除临时 Key；`captureProviderResponses` 仅用于保存该测试的中性故事请求与响应，不保存认证头。

### 对话与创作设置

个性化姓名与自我描述参与聊天、旁白和小说创作上下文。外观设置提供对话字体、旁白斜体与预览，偏好保存在本机。小说创作支持风格预设和自由输入；百科详情支持直接重命名，批量生成数量默认 1。

## 统一世界资料

`PromoteWorldTemplateUseCase` 在 Room 事务中复制旧工坊背景与 Lore，写入 `legacy_world_mappings`、`legacy_lore_mappings`。重复操作返回原世界；旧原文保持不变。同名资料分别保留，条目记录旧类型、关键词、核心标记与来源。

创作页集中角色与世界入口，新对话和小说创作统一世界选择。世界设置通过修订条件更新名称、简介、背景、玩法与规则；生成整包保存与归入同属一个事务。已有会话和恢复草稿保留其原始设定。

`MIGRATION_19_20` 仅增加映射表与索引，保留原数据库。旧模板、旧条目及关联世界受到外键保护；删除百科条目会清空对应映射目标，保留来源记录。

## 消息搜索与小说目录

独立搜索页面在顶部输入关键词，保留最多 12 条本会话最近搜索并支持删除。搜索结果按消息 ID 分页，展示年月日、正文片段和匹配高亮。点击结果进入只读消息窗口，加载目标及前后各 8 条消息，右侧提供上一个、下一个和匹配计数。总数查询复用全文索引条件，结果缓存不保留完整正文。

小说目录复用当前故事线可见性与回复版本选择，主线直接读取主线资料；每页最多 40 条，仅投影元数据和 180 字正文前缀。章节优先使用开篇结构化标题，续写兼容正文标题和片段条目。

生成耗时保存在消息现有结构化元数据的 `generation_duration_ms` 中，在完整回复结束后写入。旧消息无需迁移，编辑保留章节与耗时信息。系统朗读按引擎长度上限分段，网络朗读通过统一播放器管理替换、停止和临时音频释放。
