# Android 当前开发与交互基线

**复核日期：2026-09-07**

> 本文取代旧的五份“从零施工”分册和三份 API 修复方案。产品边界与完成度以 [`../PROJECT.md`](../PROJECT.md) 为准；本文只维护 Android 当前架构、实现约束和可执行验收。

## 自动事件与时间线

事件提取先解析完整候选，再通过 `MessageDao.commitDerivedEvents` 的 Room 事务复核来源、查重并整批写入；复用现有有效上下文与故事线可见性查询，最多检查 20 条来源、写入 5 条事件。取消异常向上传递，同故事线/角色/原文/标题的重复事件保留已存状态。没有 schema 变化或历史记录清理。

事件操作读取当前故事线，刷新序号防止晚到结果覆盖新状态；状态写入使用明确目标值，读取失败保留已保存结果并提示重新进入。时间线显示待跟进/已解决，星标限制为 1–5。80 项定向 JVM、4 项桌面 SQLite 回归及主代码/AndroidTest 编译通过；新增 Room 原子回滚、重复提取与来源变化用例仅编译，未设备运行。自动摘要、百科沉淀和独立上下文开关不属于该事件保护路径，仍需后续处理。

## 自动摘要提交与展示

`MemoryCompactionStore` 使用现有 AppDatabase：一个短事务读取前三段可见摘要、当前故事线修订和下一个有界原文页；模型调用在事务外；提交事务再次读取并比较这些状态，然后分配当前故事线段序号并使用 ABORT 插入。较早历史失效、来源改变或另一个整理已推进时拒绝保存，不覆盖既有摘要。损坏 JSON、空/非字符串摘要不再退回原文前缀，失败不推进进度；取消继续向上传递。

保存成功后尝试立即更新当前故事线记忆面板；空状态解释自动整理与原文保留，摘要使用信息标签，旧关键事实 JSON 为 null 时不会直接调用空值的列表操作。84 项定向 JVM 与主代码/AndroidTest 编译通过，新增 Room 故障恢复/重复提交用例仅编译；界面未设备实测。不改 schema、不清理旧记录。既有删除路径的摘要尾部失效、每条 200 字摘要输入截断、百科沉淀和独立上下文开关仍待处理。

## 内置目录与生成记录

当前示例为“雾港来信”：一个百科、一个世界、沈照与林汐两个角色。`builtin_catalog_v2` 控制一次性初始化，用户删除后不补回。旧 `legacy_seed_v1` 资源只供版本迁移识别，不再进入初始化入口。

`BuiltinCatalogUpgrade.installCurrent` 用一个 Room 事务完成原样旧资料识别、无引用检查、归档和新目录写入。不修改 schema（仍为 19）；旧目录只要包含用户编辑、自定义角色、历史/配置/任务引用或外部百科关系，就保留该部分。原样移出的行以版本 1 快照保存在 `app_config.builtin_catalog_retired_v1`；`restoreRetiredCatalog()` 为维护恢复入口，恢复前检查原 ID 未被占用，冲突时整笔回滚，不覆盖现有资料。新目录写入失败时旧目录移除也回滚，下次初始化重试。该升级/恢复路径有 instrumentation 用例，本批仅完成代码编译，未运行设备迁移。

角色按置顶时间、收藏、创建时间、稳定 ID 排列；全部和百科筛选一致。导入会生成新的本地创建时间，编辑旧角色不再改变普通排序。

生成页展示最近 150 项，进行中优先，支持分类、错误详情、取消确认及结果跳转。暂停设置保存到已有加密偏好，当前请求返回并完成本步骤保存后暂停；不是中断供应商正在处理的请求。继续/失败重试保留进度；百科条目、时间线和进度同事务提交，取消与晚到保存由任务状态检查隔离。角色人设与模板生成期间若被手动修改，结果不覆盖用户编辑。

## 对话平台与模型

模型页可保存多个平台，每个平台独立保存 Key、地址、模型清单和默认模型。预设只保留 DeepSeek、OpenAI、硅基流动、Anthropic、自定义；选择其他预设会建立新的平台草稿，旧平台保持原样。手动改变地址时清空草稿 Key 与旧模型清单。

优先获取平台模型列表，失败或不支持时允许按行/逗号手动输入。获取过程可取消，失败不会清除已有模型。Anthropic 按 [Models API](https://platform.claude.com/docs/en/api/models/list) 使用原生认证与游标分页。

聊天顶部展示线路/模型入口，按平台分组并可搜索。选择保存到当前会话，明确覆盖本场角色与旁白线路；发送开始时固定整轮配置，生成期间切换只影响下一轮。未显式选择时继续遵循原有角色/世界/公共线路规则。

平台数据位于既有加密偏好中的 `model_platforms_v1`，版本为 1。旧公共线路在首次保存前只做读取映射；首次保存平台清单、当前平台与旧字段使用同一次偏好提交。损坏或未知版本不会被自动覆盖。不修改 Room schema，不把 Key 放入会话模型选择字段。

## 消息撤回与来源保护

聊天长按撤回先显示原文片段及影响检查，普通消息明确确认后执行；检查失败可以重试，提交失败会重新检查，不自动再次撤回。故事线或会话切换关闭未提交窗口，生成中拒绝撤回。成功后以邻近消息重新加载有界历史窗口，避免从旧剧情跳回最新。

`MessageDao.previewRecallInSession` 提供预览；`recallInSession` 和底层 `delete` 在 Room 事务内重新保护故事线/检查点起点、跨故事线编辑来源与编辑版本。`SessionBranchDao.insert` 在同一事务检查来源属于当前会话且仍存在，避免撤回后创建悬空起点。既有同线 swipe 回复仍允许撤回并回退剩余版本，确认窗口说明该行为。

仅凭 `includeInContext=false` 不能证明一条消息是媒体。新生成图片/语音在既有 `structuredContentJson` 写入 `derived_media_version=1` 与 `derived_media_kind=image/voice`；连带撤回必须同时满足同会话、同故事线、父消息一致、排除上下文及已知标记。旧无标记、格式损坏、未知版本和普通排除消息保留，用户可单独操作。没有 schema 升级或旧行回填，Room 版本仍为 19，标记不嵌入消息 ID。

撤回沿用事务内收藏/派生记忆处理及提交后未被其他消息引用的应用私有文件清理；失败不会先清理文件。2026-09-07 的 77 项定向 JVM、2 项桌面 SQLite 和主代码/AndroidTest Kotlin 编译通过。新增 Room/Compose 用例仅编译，未连接设备，系统返回、小屏、真实事务及文件清理仍需设备验收。代码回退不恢复已经确认撤回的原文，旧损坏来源不自动修复。

## 1. 路线与边界

- 工程：`mojing/android/`；
- 技术：Kotlin、Jetpack Compose、Room、Hilt、OkHttp/Retrofit、DataStore；
- 最低 SDK：26；当前 `compileSdk=36`、`targetSdk=35`；JDK 17；
- 数据：会话、消息、角色、百科、模板和配置默认保存在手机本地；
- 网络：应用直接访问用户配置的模型、图片或语音 API；
- 用户体系：没有注册、登录、Token 用户隔离或云端账号；
- 移动端路线：不使用 WebView、Capacitor 或 PWA APK。

第三方 API 的认证 Header 只是供应商 Key，不代表本应用存在用户登录体系。

## 3. 聊天输入框与软键盘（IME）

### 3.1 产品验收标准

用户点击输入框后：

1. 输入框获得焦点并唤起软键盘；
2. 整个输入栏始终完整显示在键盘上方；
3. 当前最后一条消息不会被输入栏或键盘遮住；
4. 键盘出现/收起时页面不应周期性跳动、顶飞或留下双倍底部空白；
5. 多行输入增长时输入栏有最大高度，消息列表仍可滚动；
6. 返回键第一次关闭键盘/覆盖层，第二次才执行页面返回；
7. 发送、停止、附件、更多菜单、旁白/选项弹层与键盘状态一致且可预测。

### 3.2 Insets 规则

- Manifest 保持 `windowSoftInputMode="adjustResize"`；
- `Scaffold`、页面根布局、消息列表和输入栏之间必须明确谁消费 `WindowInsets.ime`；
- 同一条布局链只能有一处承担 IME 底部避让，避免根布局和输入栏同时 `imePadding()`；
- 导航栏 Insets 与 IME Insets 不能简单累加成双倍间距；
- 消息列表底部 padding 应包含输入栏实际高度，并在 IME 动画期间保持稳定；
- 如启用 edge-to-edge，必须在真机验证状态栏、手势条和三键导航；
- 不用固定 dp 猜测键盘高度，不监听全局布局后反复手动改高度。

### 3.3 焦点与覆盖层规则

| 操作 | 预期 |
|---|---|
| 点击输入框 | 请求焦点并显示键盘；光标和已输入草稿保留 |
| 点击发送 | 请求只触发一次；连续输入策略保持一致，不出现焦点闪烁 |
| 点击停止 | 停止生成，不误清空当前草稿，不强制弹回键盘 |
| 系统返回 | 优先关闭键盘，再关闭菜单/抽屉/弹层，最后离开页面 |
| 打开附件/文件选择 | 先处理键盘和焦点，返回后恢复草稿；不能出现键盘压在选择器/Bottom Sheet 下方 |
| 打开更多菜单或对话框 | 与 IME 互斥，或明确保持在键盘上方；关闭后焦点状态可预测 |
| 点击快捷词 | 替换当前选区或插入当前光标位置；插入后光标位于新文字末端并恢复输入焦点 |
| 切换会话/分支 | 结束旧输入状态，不能把草稿或焦点串到新会话 |
| 旋转/分屏/切后台 | 恢复后输入栏可见，草稿和生成状态不无提示丢失 |

### 3.4 消息列表协同

- 输入框获得焦点时，仅在用户原本接近底部时自动保持最后消息可见；
- 用户主动上翻阅读历史时，键盘或新 token 不应强抢滚动位置；
- 流式生成、输入栏高度变化、键盘动画不能产生循环滚动；
- 列表空状态也要为输入栏和 IME 留出正确空间；
- 必要时使用 Compose 的 Bring-Into-View/Insets 能力，但不能同时叠加多套自动滚动来源。
- 打开/刷新只读取最近 80 条当前故事线消息；向前/向后按稳定消息 ID keyset 每次 40 条，UI 窗口最多 200 条；
- 搜索使用按会话隔离的外部内容 FTS4：用户原文或模型生成消息的可见正文经 NFKC/小写规范化后生成 Unicode 单码点与双码点 token，FTS 候选再以规范化可见正文复核；结构标签和未选择选项不进入 v2 索引。索引可按版本重建，旧库升级期间每事务补齐 256 条并对未完成区间保留精确回退，不改原消息；
- 搜索和收藏跳转必须能读取未加载目标附近窗口，不得要求先把整段历史装入内存；
- 搜索结果、收藏、分支来源/自动标题与会话列表摘要共用用户可见正文：模型消息保留旁白、思考、台词和普通正文，排除结构标签与未选择选项；用户输入原样显示；
- 主线聊天导出先固定最大消息 ID，再按 ID 每页 256 条直接写入目标流；不得先构造完整消息列表、JSON 树、字符串或字节数组。目标 URI 必须在 IO 线程打开并响应取消；失败与取消只关闭流、提示文件可能不完整，不删除可能由用户选择覆盖的既有文档；
- 酒馆聊天导入的文件读取使用 IO 线程，解析与批次构造使用后台计算线程；导入期间禁止重复触发和并发导出。当前 JSON 导出只包含主线，界面必须明确该范围；
- 非主线消息查询使用由分支父链派生的可见区段，并以区段作为外层按 `(sessionId, branchId, id)` 范围读取；分支事务同步维护，启动时校验修复，禁止重新引入逐消息递归父链判断；
- 自动摘要和事件只读取当前故事线可见的记录：普通分支继承分叉点前仍有效的祖先记录，编辑替代会排除覆盖旧消息的记录；摘要 owner 从最近覆盖终点后按消息 ID keyset 读取最早一个完整批次，不复用模型最近 400 条窗口，并在 `LIMIT` 前投影当前故事线有效 swipe。每批只计用户、角色与旁白消息，新事件记录故事线与原文消息 ID。角色状态、摘要、事件、通用记忆、百科沉淀和召回查询中的模型生成消息统一剔除思考标签与未选择选项，用户输入保持原文。删除消息必须与覆盖或绑定该来源的自动摘要、通用上下文记忆和事件节点失效处于同一 Room 事务；
- 记忆抽屉必须展示摘要的原文消息范围和事件的精确来源；点击复用聊天历史按 ID 定位，来源未加载时只读取目标附近窗口。旧数据没有有效来源 ID 时显示不可跳转说明，不猜测来源；
- 用户纠正独立存入 `session_memory_corrections`，全会话记录在所有故事线生效，分支记录只在精确分支生效。自动摘要、通用记忆重建/清空和来源消息删除不得改写或删除纠正；角色与旁白在自动记忆之前只注入一次；
- 通用上下文记忆只有 `isValid=true` 时才能进入角色或旁白 Prompt。横滑、成功重生成、正文修改、删除和撤回后的采用回退必须与真正受影响故事线的 UCM 失效处于同一个 Room 事务；重复选择当前版本不失效，不可见的父线和兄弟线不跟随改写。旧派生内容保留但不注入；下一次成功更新不得复用失效事实或旧来源范围；
- 自动更新必须先预留故事线 `revision`，并只在该 revision 仍是最新时提交；后发更新、故事线变化和显式清空都必须推进代次，旧模型请求不得重新激活过期事实。自动积压在 120 条以内按每批 40 条有界合并并只提交最终结果；更多时不得截断旧剧情或无提示连续调用模型，必须保留现状并引导用户手动重建。手动重建从当前故事线最早有效消息开始按 ID keyset 分页，不得预先删除旧记录或把旧摘要带入首个 Prompt，全部页面成功后才单次原子替换；断网、模型错误、无效响应、取消、代次过期与空消息保留原记录并明确反馈。显式清空保留无正文的失效记录以阻止在途结果写回；
- 最近一次纠正依据只保存在当前 Chat ViewModel：角色或旁白 Prompt 构造完成后才更新当时快照，失败或图片任务不伪造也不清空；抽屉按当前故事线展示并明确不代表模型已成功回复，不写入 Room 或日志；
- “重新生成”只对当前故事线最后一条正在生效的角色回复开放；使用目标回复之前的持久化上下文，并复用原 swipe 组的原子切换。历史角色/旁白内容使用“编辑”或“从此处分支”，不得把物理消息 ID 当叙事位置或为此新增位置 schema；
- swipe 采用状态由 schema 18 的稀疏 `branch_swipe_selections` 按会话、故事线和版本组保存；`messages.includeInContext` 只作为旧库冻结默认。模型热路径必须优先显式覆盖，其次采用当前故事线可见的冻结默认，默认不可见时退到最新可见版本，不能因分叉锚点较早而漏掉整组回复；
- 模型近期上下文最多读取 400 条后再按 Token 预算裁剪，原始历史继续完整保存在 Room。

## 4. 主交互闭环

### 4.1 启动与导航

- 首次启动直接进入本地应用，无登录页；
- 数据初始化失败显示错误和 Retry；
- 底部导航只保留“对话 / 创作 / 设置”；小说创作、角色、百科和设定工坊由创作页统一分流；
- 底部导航由 `MainAppBottomNavigation` 统一路由，页面不重复传递所有主导航回调；
- 页面内导航统一使用栈顶单例策略，快速重复点击同一入口不得堆叠重复页面；
- 路由参数缺失或不合法时自动返回对应根页，不能静默显示空白页或误进入新建流程；
- 桌面快捷方式、小组件和回复完成通知统一由 `MainActivity` 解析为现有导航目标；冷启动与 `onNewIntent` 复用同一入口，通知中的合法会话 ID 直接打开对应对话；
- “对话”和“创作”主导航分别复用 `returnToSessionHome()`、`returnToCreationHub()`，先弹回对应根页面再安全补建路由，不恢复旧子页面造成点击无反应；
- 页面上可见的设置、任务等跳转回调为必填参数，禁止使用默认空回调隐藏漏接入；
- 输入栏、分支面板等核心交互组件的可见动作同样使用编译期必填回调，不允许通过默认空实现制造“按钮存在但点击无反应”；
- 对话导入、导出只保留在顶部“更多”菜单，参与者抽屉不再提供重复导入入口；聊天显示密度统一在“设置 → 外观”选择；
- 对话页顶部返回和系统返回优先弹回会话列表，不使用会恢复当前对话栈的主 Tab 导航；生成期间返回时提供“停止并退出”，确认后复用 `stopGeneration()` 清理任务再离开，不能把用户锁在对话页；
- 抽屉、详情页和系统返回遵守层级，原角色/百科/工坊路由保留；
- 创作中心顶部可返回会话主页，内容区必须在小屏设备上纵向滚动；小说创作、角色、百科和设定工坊顶部统一返回创作中心；
- 离开编辑页前保护未保存内容。

### 4.2 聊天

- 新建会话 → 参与者/线路 → 发送 → 流式回复 → 停止/重试 → 编辑/删除 → 分支/搜索；
- 每个操作有加载、失败、取消和恢复状态；
- 聊天编辑、用户纠正和会话内搜索弹层必须避让 IME；长编辑内容与搜索结果使用受限高度和可滚动区域，不能把确认/关闭动作挤出小屏。设置页提供可见的会话主页返回；会话首页搜索入口必须明确其当前仅按标题匹配，并允许一键清空；
- 新建会话、世界配置和参与角色由 `SessionCreationTransaction` 在单一 Room 事务中写入；设置中的默认世界模板必须按稳定 `templateId` 读取完整模板内容，空白/角色快捷开局继承该模板，新建弹窗允许明确选择“无”。模板已删除时回退自定义世界；失败保留弹窗并提示重试，不留下半套会话。空白与完整配置创建共用单一进行中状态，首次提交完成前锁定重复创建、取消与系统关闭并显示进度；
- 世界工坊发起的新故事请求以模板 ID 和递增加载版本驱动面板；即使会话页状态被恢复且面板已打开，也必须取消旧读取并应用最新请求。模板、百科和绑定角色全部加载成功前不启用完整创建；失败显示原位重试并保留已填草稿，不静默回退错误世界；
- `ChatViewModel` 统一持有发送、旁白、重生成和生图的单一生成 owner；生成开始同步锁定 UI，停止后立即允许重试，旧任务回调不得清理或覆盖新任务状态；
- 每次生成固定当前分支快照，分支切换/创建与生成串行，结果只能写回该快照分支；
- “从此处分支”在 transition owner 内按当前会话和当前可见故事线回读源消息后才能落库；旧菜单回调、跨会话 ID、已撤回或已被当前编辑故事线替代的消息必须拒绝。读取/写入失败保持原故事线并显示重试反馈，不能先切换 UI 或留下空壳分支；若提交后刷新失败，必须明确提示重进，不能让用户误以为未创建而重复提交；
- 故事线切换先按当前会话真实分支清单校验目标，再用显式目标 ID 一次加载消息、记忆、事件、附件和选项；目标已失效、分支表读取异常或目标数据加载异常时保持原故事线且不更新重进位置。若目标在校验后的二次读取前消失，刷新层回主线并必须说明原因；
- 编辑消息的分支事务提交与自动续写准备是两个状态：替代消息和附件副本提交后，必须按新分支完整加载消息、记忆、事件和选项并确认当前线一致，才可关闭编辑框；只有用户消息编辑在此后启动角色回合。提交后刷新失败提示重新进入，不得在旧故事线上生成，也不得把已保存编辑误报成可安全重试；
- 多角色发言与自动媒体生成在整个流程中保持生成状态；停止时删除未完成的媒体占位及其临时文件，不遗留永久“生成中”；
- 自动配图/语音消息以 `parentMessageId` 绑定产生它的角色回复；它们不构成新的剧情回合。尾回复重生成可以跳过明确归属的媒体，swipe 只展示当前采用回复的媒体；旧版本消息、附件和文件保留，切回时恢复。历史无归属媒体不自动猜测或改写，继续保守阻止重生成；
- swipe Pager 在生成期间不可滚动，并在生成状态变化时回到当前故事线采用版本；ViewModel 切换入口与生成/故事线 transition owner 串行，按当前故事线重新校验目标消息和组 ID，再写入该故事线的稀疏覆盖。主线、父线和兄弟线选择互不改写；新故事线只继承分叉点可见的父线显式覆盖；
- 撤回消息由会话隔离的 Room 事务处理；若物理目标是某些故事线当前采用的 swipe 回复，删除其明确归属的自动媒体后，分别为这些故事线选中最新剩余可见版本。事务提交后只删除已经没有附件引用、且确属本应用私有会话附件或语音目录的精确文件；生成或故事线切换期间入口禁用并由 ViewModel 再次拒绝；
- 停止发生在本地提交前时保留输入和附件选择；远程重生成成功后才由同一 Room 事务绑定版本组、写入新版本并更新当前故事线选择，失败或空回复不提前修改旧消息；
- `ImageApiService` 使用绑定 `Call.cancel()` 的可取消协程桥接，响应解析与文件写入调度到 `Dispatchers.IO`；`ImageRepository` 不吞 `CancellationException`；
- 删除无生产引用且重复、绕过分支/记忆链的 `SendMessageUseCase`、`StreamGenerateUseCase` 及旧测试；
- 当前会话和当前分支的数据过滤一致。
- 角色与旁白的动态选项复用 `OutputProcessor → StructuredParser → MessageAction.SelectChoice → sendMessage` 单一链路；既支持严格 XML 和带 `id`、`type` 等属性的 `<CHOICES>` / `<OPTION>`，也兼容模型常见的尾部编号、项目符号、Markdown 标题、引用式/中文编号和 `<CHOICES>` 内非严格列表。明确标题后的列表即使后面还有结束语也要恢复，明确区块允许单项；无标题普通清单继续保守识别。选项不得重复显示在正文或作为未选择的剧情内容回送模型；冷启动从实际采用且进入上下文的尾回复恢复选择条及来源消息 ID，自动配图/语音追加的派生消息不能遮蔽它。当前选项只在输入栏上方提供一个可提交入口，输入法仍打开时也必须位于已有 `imePadding` 安全区上方可见，历史气泡只读回看。提交必须同时匹配当前故事线、来源消息、采用中的 swipe 版本和解析结果，历史/过期选项不得写入用户消息。
- 消息的复制、朗读、引用和编辑复用 `StructuredParser` 与同一个气泡正文格式：旁白、想法、台词及普通正文按界面可见顺序输出，去掉结构标签及所有未选择选项。引用预览和真正发送的引用前缀必须一致；纯选项消息不覆盖剪贴板、不进入引用状态，空朗读给出反馈。
- 角色与旁白共用 `ContextBuilder.searchWorldContext` 召回当前会话模板 Lore 和绑定百科；旁白以当前故事线最近消息与用户方向为检索文本，并由 `PromptBuilder` 注入命中内容。模板或百科缺失、没有相关命中时返回空上下文并继续生成，不复制 DAO 查询或新增平行检索链。
- 小说创作的剧情走向和旁白回复分别维护提交状态：剧情走向只有在用户消息落库后才清理草稿；提交前失败保留可重试输入，提交后刷新失败说明内容已保存并停止本轮模型请求。流式 `Done` 尚未写入时报告本地保存失败，回复已经落库但刷新失败时说明已保存并要求重新进入，不重复发起生成；取消继续向生成 owner 传播。

### 4.3 本地资料与媒体

- 角色、百科、工坊 CRUD 后列表立即刷新；
- 智能生成世界先在写事务外完整解析模板与 Lore，再由 `SaveWorldTemplatePackageUseCase` 在单一 Room 事务中整包替换；更新已有模板保留本地身份与置顶等设备状态，Lore 任一写入失败时模板和原 Lore 必须一起回滚；
- 智能生成世界的远程阶段必须有停止入口；切换分页、顶部/系统返回或底部导航先确认，停止后保留表单且不写入未完成模板。进入整包本地保存后显示独立状态并暂时阻止离开，不能让页面取消打断事务；
- 角色列表删除统一进入 `DeleteCharacterUseCase`，同时清理绑定百科中明确关联的角色镜像；不得再新增只转发 `CharacterDao` 的平行 Repository/UseCase；
- 导入后可打开，导出后可再次导回；
- 权限拒绝、URI 失效、音频播放失败、图片生成失败显示可读原因；
- 含图片附件的消息长按后可保存到系统相册；无图片消息不显示该动作，多图按一个单飞任务保存并报告数量。Android 10+ 使用 MediaStore pending 提交，Android 8/9 才请求 `WRITE_EXTERNAL_STORAGE`；失败或取消清理新建目标，不修改或删除聊天原图；
- 用户与角色消息图片单击进入共用全屏预览，图片按可用空间完整适配，并显示加载或读取失败状态；顶部关闭与系统返回退出预览，关闭后不得遗留或误开消息操作菜单；
- 备份先写临时文件并校验，恢复失败保留原 Room 数据库；
- 导出和日志不得包含 API Key、签名密码或应用私有绝对路径。

### 4.4 设置入口

- 只展示 Android 运行时有明确读取方、会真实影响本机业务的配置；
- 顶层按“模型 / 创作 / 个性化 / 统计”分组；模型页通过“对话 / 配图 / 朗读”切换一次只编辑一条线路，API Key 默认隐藏；
- 对话、配图和朗读各自复用统一的供应商预设、手动地址/模型和连通测试；高级思考、剧情记忆及诊断日志默认折叠；
- 默认世界模板和参考百科必须从本机现有资料中选择，不要求用户手填内部 ID；
- Web 的输出后处理由 FastAPI 正则规则服务负责。Android 尚无对应本地处理 owner，因此不保留仅写入 `output_rules_json`、聊天完全不读取的平行设置页；
- 删除 UI 或代码属性不得主动清理设备 SharedPreferences 中的旧键值，避免把结构收敛扩大成用户配置删除。

### 4.5 小说创作

- 入口位于创作中心，不再与底部主导航或对话顶部工具重复；
- 输入故事背景后，可选世界模板、百科、参与角色、开篇走向、文风和首次连续生成 1～3 章；
- 直接生成小说正文并创建“小说创作”会话，不再生成候选、要求选择或执行二次采用保存；
- 生成使用现有公共对话 API、`LlmRetry` 和统一会话创建 UseCase，不维护第二套供应商或 Room 表；
- 章节写入普通旁白消息，最后一章携带本轮动态生成的后续走向；进入会话后，输入下一段剧情走向会由小说作者继续写正文；
- 用户明确写下的否定设定、秘密归属和人物知情范围会写入会话世界设定并持续生效；初次生成与续写的动态选项还会经过本地一致性过滤；
- DeepSeek 模型复用同一写作链路，通过模型感知的采样和提示约束加强设定核对、知情边界与连续性，不维护独立供应商实现；
- API 未配置、解析失败或网络中断时必须保留表单内容；小说正文不自动写入百科。
- 初次小说生成的远程阶段必须可停止；顶部/系统返回和底部导航先确认，停止后保留故事背景、走向、文风与选择。进入会话和章节本地保存后显示独立状态并等待完成，不把保存阶段继续伪装成模型生成。

## 5. API 线路规则

- 预设只负责填充默认 Base URL/模型/协议，不代表供应商永久可用；
- 保存前规范化 Base URL，避免重复拼接 `/v1` 或完整 endpoint；
- 对话、图片、语音协议分别探活，不用“对话可用”推断其他能力可用；
- LLM、图像和语音的普通 OkHttp 请求统一复用 `CancellableOkHttp`，底层 `Call` 必须与协程取消绑定；响应解析/文件写入不得阻塞主线程，也不得把 `CancellationException` 转成普通失败；
- DMX Seedream/Wan 生图走 Responses API，Gemini 生图走原生 GenerateContent；不能把所有模型都发送到 OpenAI `/images/generations`；
- 生图结果统一物化 URL、纯 Base64 或 Data URI；封面处理后清理临时文件，聊天附件在消息与附件记录落库前由调用链持有，取消或失败必须补偿删除；
- TTS 文件在调用方取得路径前仍由生成函数负责；取消时必须删除已创建但尚未交付的文件；
- 401/403、模型不存在、协议不兼容、限流和超时要映射成用户可读错误；
- Key 只保存在本机配置中，错误文本和日志必须脱敏；
- 供应商变化时更新代码和测试，不再创建新的“修复方案 V2/V3”文档。
