## 目标

我把玩家百科库定位为“运行时事实源”，不是普通备忘录。会话绑定百科库后，AI 提示词会额外注入命中的百科条目，并把这些条目作为专有名词、人物关系、地点、事件和能力判定的优先依据。

## 编辑与 AI 补全规则

- 玩家手动填写的标题、摘要、正文、标签和字段是最高优先级事实。
- **Android** 端「结构化 Meta」已与 Web **`SOURCE_FIELDS`** 补充对齐（页面标题、获取时间、适用范围等），并支持 **扩展键** 行编辑（未列入 schema 的顶层键；复杂值可填 JSON 字面量）。
- 字段默认都可以不填；前端提供 `custom_fields`，玩家可以追加项目专属字段。
- AI 只能补齐空字段，不能改写用户原文。
- AI 补全内容必须标记为 `AI补全/待确认`，审核前不能等同于官方设定。

## 来源口径

每条来源导入内容会写入 `meta_json`：

- `source_url`: 原始页面 URL
- `source_page_title`: 来源页名
- `source_retrieved_at`: 抓取时间
- `source_license`: 来源许可
- `source_trust_level`: `official / wiki / community / manual / unverified / template`
- `verification_status`: `verified / fetched / pending / manual_unverified / template`
- `canon_scope`: 正史范围
- `canon_conflicts`: 冲突版本
- `unknown_fields`: 来源没有覆盖的字段

## API

```text
GET  /api/encyclopedia/entry-types
GET  /api/encyclopedia/schemas
GET  /api/encyclopedia/template-modules
GET  /api/encyclopedia/source-policy
POST /api/encyclopedia/{id}/bootstrap-template
POST /api/encyclopedia/{id}/import-sources
```

来源导入支持 MediaWiki/Wikipedia URL，也支持 `标题|URL|entry_type` 的前端批量输入。默认 `dry_run=true` 只预览，不写入数据库。

## 验证路径

- 协议级：检查 `/entry-types`、`/schemas`、`/bootstrap-template`、`/import-sources` 的状态码和字段。
- 行为级：模板补齐后再次查询条目数量；会话绑定百科后，生成调试信息会出现 `encyclopedia_hits`。
- 反证级：空来源、非法 URL、缺失百科 ID 必须返回明确错误，不能静默成功。
