# 酒馆生态与角色卡兼容调研

> **当前使用边界（2026-07-19）**：本文保留为角色卡、WorldInfo 与酒馆生态兼容研究，不是当前需求清单或完成度证明。产品边界以 [`../PROJECT.md`](../PROJECT.md) 为准；导入导出必须本地可往返、保留扩展字段且不得携带 API Key。

> 目的：对齐「酒馆」类 LLM 聊天前端的常见能力与数据形态，为本项目（会话 + 多角色 + 百科/世界）在 **导入/导出、角色卡、世界书** 等方向的兼容策略提供参考；并补全 **对话上下文与记忆管线**、**UI 参考边界与可切换布局** 等核心层说明。
> 仓库事实来源仍以根目录 [`PROJECT.md`](../PROJECT.md) 为准。
> 文档导航见 [`README.md`](./README.md)。

## 1. 代表项目概览

| 项目 | 技术形态 | 典型用户画像 |
|------|-----------|--------------|
| [SillyTavern](https://github.com/SillyTavern/SillyTavern) | Node.js 本地/自托管 Web 前端 | 重度自定义：多后端、扩展、正则、世界书、群组 |
| TavernAI（经典） | 早期 Web 酒馆形态 | 社区角色卡与 ST 生态大量互通 |
| [Agnai.chat / agnai](https://github.com/agnaistic/agnai) | Web 前端，多提供商 | 强调任务/编辑器导入导出，采纳 **Character Card V2**（含 `character_book` 等） |
| 其他「酒馆」fork/衍生 | 多基于 ST 或兼容其数据习惯 | 角色 PNG、WorldInfo JSON、预设 JSON 等 |

**SillyTavern** 是当前事实上的「兼容基准」：社区分享的 **PNG 角色卡**、**WorldInfo（世界书）**、**预设 JSON** 多按 ST 或其插件约定生成。

## 2. SillyTavern 可借鉴的功能点（产品向）

以下不追求逐项复刻，可作为能力地图与优先级讨论素材。

1. **多后端与 OpenAI 兼容栈**
   同一 UI 下切换 OpenAI 兼容 API、本地推理（如 text-generation-webui）、Kobold 等；本项目已走「每角色 API Key + 自建后端」路线，可继续强化 **统一 OpenAI 兼容入口** 与错误提示。

2. **World Info / Lorebook（世界书）**
   按关键词、深度、预算将条目注入上下文；与当前 **世界百科 + 会话绑定世界** 概念接近，可映射为：百科条目 ↔ WI 条目，注入策略 ↔ 「检索/摘要/分段记忆」管线。

3. **角色卡（Character Card）**
   ST 侧常见：`description`、`personality`、`scenario`、`first_mes`、`mes_example`，以及 V2 扩展字段（`system_prompt`、`post_history_instructions`、`alternate_greetings`、`character_book` 等）。
   本项目后端已有 **结构化人物卡 JSON**（见 `memory_service.DEFAULT_CARD` 与 `import_character_profile` 抽取逻辑），与 V2 可做 **字段级映射表** 而非 1:1 复制 ST 内部存储。

4. **扩展（Extensions）与社区插件**
   ST 通过扩展增强 TTS、生图、自动化等；本项目 Web/Android 已有多模态与设置页能力，长期可定义 **稳定扩展点**（Webhook、脚本钩子）而非复制 ST 插件模型。

5. **正则/脚本与聊天流程自动化**
   ST 用正则改写模型输出或触发动作；若引入需权衡安全与可维护性，建议优先 **服务端可控的轻量规则**。

6. **群组聊天与多角色轮次**
   ST 支持多 bot 同会话；与本项目 **多参与者 + 发言计划** 方向一致，可对照 UI 与 API 设计。

7. **导入导出习惯**
   - 角色：**PNG（内嵌 tEXt/zTXt 等块中的 JSON）** 或纯 **JSON**
   - 世界书：**JSON**
   - 聊天：**JSONL/HTML** 等（各 fork 不一）
   兼容策略见下文第 4 节。

## 2.5 对话上下文与角色记忆（核心层对照）

> 初版正文侧重 **数据互操作（卡/世界书/聊天记录文件）**；本节补全 **「每一轮回复生成前，上下文如何拼装、记忆如何进入模型」** 的调研要点，并与本仓库实现挂勾（以代码为准，随迭代更新）。

### SillyTavern 侧（概念归纳）

- **Prompt 分层与拼装**：Main / NSFW / Jailbreak、角色卡各字段、作者注释、预设（Preset）、正则输出前后处理等，最终汇入发给模型的 **messages 或等价文本管线**（具体顺序依版本与用户配置）。
- **聊天历史**：受 `context size` / `max tokens` 约束；常配合 **滑动窗口**、可选 **对话总结（summary）**、以及社区/插件提供的 **向量记忆、长期 Lore** 等。
- **世界书（World Info）**：按关键词、深度、优先级、预算（token budget）将条目**动态注入**上下文；与角色卡内嵌 `character_book` 可能叠加，需防重复与超预算。
- **示例对话**：`mes_example` 等常以 **few-shot** 形式插入（位置与格式依预设与前端实现）。

### 本仓库侧（真源与落点）

| 能力维度 | ST 常见叫法 | 本仓库负责模块（概念，需对照代码） |
|----------|-------------|--------------------------------------|
| 近期对话 | Chat history | 后端 `_list_visible_messages`、`recent_message_limit`、分支 `branch_id`；Android `SlidingWindowBuilder` 等滑动窗口 |
| 系统/人设拼装 | Main / char | 后端 `build_group_prompt`、参与者摘要；Android `PromptBuilder` + `ContextBuilder` |
| 结构化角色记忆 | Card memory（概念） | `character_card_json` 与 `_select_relevant_memory_hits`；会话角色状态 `dynamic_state_json`、关系/事实等同类命中 |
| 中期分段摘要 | Story summary（概念） | `SessionMemorySegment`；`memory_v2_service.build_context_memory`；Android `memorySegmentDao` 与摘要拼接 |
| 百科 / Lore | WI / Lorebook | `_get_encyclopedia_hits`、`_get_lore_hits`；Android `EncyclopediaSearcher`、`LoreSearcher` |
| 资料库 RAG | 扩展能力 | `get_context_chunks`（Data Bank 多 scope） |
| Token 预算 | Context budget | 角色 `max_tokens`、各处 `token_budget`；前后端 Token 条/估算展示 |

### 差异与互操作启示

- ST 将大量开关暴露在 UI（预设、世界书、正则、扩展）；本项目将复杂度**更多收束在后端拼装管线 + 会话绑定世界/百科**，UI 侧重会话抽屉、记忆片段、世界开关等。
- **角色卡 / WorldInfo 导入**若只做字段落库、而不把 `character_book` / WI 映射进 **百科检索或 Lore 命中管线**，则对话中**不会出现**与 ST 等价的「动态注入」效果——互操作设计阶段需显式决策映射策略（见 §4.2 B 层与 §5 `character_book` 行）。

## 2.6 UI：参考酒馆信息架构，独立视觉与「布局/密度」可切换

- **可参考（信息架构与工作流，非像素级克隆）**：侧栏会话列表、右侧世界/角色/世界书抽屉、按「关键词 + 优先级 + 预算」管理 Lore 的心智模型、重度用户常用的高级设置分区——用于降低从 ST 迁来的学习成本。
- **不建议**：整站 1:1 仿 ST 皮肤与组件堆砌（维护成本高、易与「AI 味」同质化，且无必要绑定单一开源 UI）。
- **「更好一套 UI + 支持切换」的产品化建议**（与「数据层不克隆 ST」并行）：
  1. **外观主题**：已由 Web `data-theme` 多套 token 负责（与酒馆皮肤解耦）。
  2. **聊天布局/密度预设**（建议新增）：例如 **「默认」**（当前清晰留白）、**「高密度」**（缩边距、同屏多一行历史、侧栏更窄——对齐重度用户习惯，视觉仍为本项目体系）、**「阅读」**（行长与气泡对比度优先）。Web 可用 CSS 变量 + `localStorage`（`data-chat-density`）；Android 可用 **DataStore** 存 **`chat_density`**（舒适 / 紧凑 / 阅读，与 Web 三档对齐）。
  3. **验收原则**：同一 OpenAI 兼容栈下，**切换布局预设不得改变送入模型的 messages 内容**（避免「换肤换 prompt」）；若某预设折叠了「世界/记忆」面板，需在文案中说明**仅影响可见性、不改变已绑定会话配置**。

## 4. 与本项目的兼容思路（导入 / 导出）

### 4.1 当前工程已有能力（摘要）

- **后端**：`export_service` 会话目录镜像、ZIP 备份；会话/消息/参与者等结构化导出。
- **WorldInfo → 百科（批量）**：`POST /api/encyclopedia/{encyclopedia_id}/import-worldinfo`（请求体 `json_text`）；解析 **顶层数组**、**`{ "entries": [...] }` / `entries` 对象 map**、`lorebook` / `data` 数组等（与 `iter_worldinfo_entries` 一致），关键词等写入条目 **`meta_json`**（如 **`wi_keys`**、`wi_secondary_keys`）。**Web**：百科侧栏 **「导入 WorldInfo JSON」**。**Android**：百科详情 **粘贴 / 文件（OpenDocument）** + **`WorldInfoImportParser`** 写入 Room。
- **聊天记录（酒馆 mes / JSONL）**：**Web** + 后端 **`POST /api/sessions/{id}/import-tavern-chat`**；**Android**：聊天顶栏 **上传图标** 或侧栏 **参与者 → 导入酒馆聊天记录**（`TavernChatImportParser` + Room，`structured_content.st_import` 与 Web 对齐）。
- **Android**：会话导入由 `TavernChatImportParser` 负责；角色、百科和备份使用各自的 JSON/ZIP 编解码与 ViewModel 流程。
- **角色**：后端支持从原始设定 **LLM 抽取** 到结构化卡；与 ST 的「现成 JSON 文件」路径不同，可并存。**PNG 角色卡（chara_card_v2）** 见 `PROJECT.md` §二.8 / §八（Android 列表导入 + 编辑页导出）。

### 4.2 建议的兼容分层

| 层级 | 内容 | 说明 |
|------|------|------|
| A. 互操作优先 | PNG 角色卡、V2 JSON | 解析 PNG 内嵌 JSON 或纯 JSON → 映射到 `Character` + `CharacterProfile` / persona 字段 |
| B. 世界数据 | WorldInfo JSON | **已提供批量落库路径**：后端见上 **§4.1**；条目 **`meta_json`** 保留关键词等供检索扩展；**对话中动态注入仍走既有百科/Lore 命中管线**（与 ST「世界书预算注入」非 1:1，见 §2.5 差异说明）。 |
| C. 聊天记录 | ST JSONL 等 | 只读导入消息序列为可选能力；导出可采用本项目自有 JSON/ZIP，避免承诺全方言 |

### 4.3 解析与容错

- PNG：使用标准库读取 **文本块** 中的 JSON；失败时降级为「仅作头像」+ 提示用户另存 JSON。
- **未知扩展字段**：写入 `extensions` 或单独 JSON 列，避免丢弃社区卡信息。
- **编码**：统一 UTF-8；换行与示例对话格式在映射时规范化。

## 5. 角色卡字段映射（概念表）

以下为 **SillyTavern / V2 常见字段** → **本项目概念** 的粗映射，实现时需对照实际 ORM 与 API。

| 外部字段 | 本项目落点（概念） |

## 6. 结论与后续可落地项

1. **以 OpenAI 兼容 API + 结构化角色/世界** 为核心，与 ST **在数据层做映射** 比在 UI 层克隆更可持续。
2. **P0 互操作**：PNG/JSON 角色卡导入 + 本项目 JSON/ZIP 导出并存。
3. **P1（已落地）**：WorldInfo JSON → 百科批量导入（关键词等进 **`meta_json`**）：Web / Android / 后端路径见 **§4.1**；**Android** 另支持 **OpenDocument 选 `.json` 文件**（顶栏回形针或对话框「从 JSON 文件选择」），解析与后端 **`iter_worldinfo_entries`** 一致（含 `entries` 对象 map、`lorebook`/`data`）；验收与差异见根目录 **`PROJECT.md`** §二.8、§十二。
4. **P2（已落地）**：聊天记录单向导入、扩展字段原样保留（**Web**：`POST /api/sessions/{session_id}/import-tavern-chat`，`multipart`：`file` + `character_id`；会话顶栏「导入」；`mes` 原对象写入 `structured_content.st_import`；**需**该角色已加入会话；非用户发言映射为所选 `character_id`）。**Android**：聊天顶栏 **上传** 或侧栏 **参与者** 内 **「导入酒馆聊天记录…」**；`OpenDocument` 读文件后写入本地 Room，语义与后端解析一致；非用户发言归为**首位参与者**。
5. **上下文与记忆**：ST 与本仓库管线对照见 **§2.5**；新功能评审时同步更新该表。
6. **UI**：参考 ST **信息架构**即可；独立视觉 + **布局/密度预设切换** 见 **§2.6**，与主题（配色）解耦（Web：`data-chat-density` 舒适 / 紧凑 / 阅读 + 侧栏 📐 循环切换，`localStorage` 持久化；**Android**：`UiPreferencesRepository` + 聊天顶栏 **Tune** + `LocalChatDensityMetrics`）。

本文随产品迭代更新；实现任务应回写 `PROJECT.md` 对应小节。
