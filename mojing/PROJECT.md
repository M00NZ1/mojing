# MoJing 产品与架构

本文记录当前有效的产品定位、数据边界、架构约束和验收原则。源码、数据库 schema 与自动测试是实现事实来源；历史施工记录不属于当前产品说明。

## 1. 产品定位

MoJing 是面向个人用户的本地优先 AI 角色扮演、长篇对话和世界设定工具。

- Web：React/Vite 客户端 + 本机 FastAPI/SQLite/文件存储；
- Android：Kotlin + Jetpack Compose + Room；
- 本地优先：角色、会话、消息、分支、百科、模板和设置默认留在当前设备；
- 单人单机：不以账号或租户作为数据边界；
- 供应商预设：DeepSeek、OpenAI、硅基流动、Anthropic、自定义；既有自定义配置不因预设移除而删除；
- Android 对话平台各自保存 Key 和模型清单，可获取模型或手动输入；聊天选择按会话保存，下一轮发送生效；
- Web 同样支持多平台与会话模型选择；手动选择优先于角色独立配置和思考模式，从下一次发送生效，同轮角色/旁白固定线路；未选择时保留角色优先、默认平台回退。
- 模型获取失败时可保留/手填模型；Web Anthropic 模型发现使用原生认证和分页，对话沿用现有兼容 Chat Completions 客户端，不承诺原生 API 的全部高级能力。

### 非目标

- 注册、登录、会员、管理后台、多租户或 SaaS 计费；
- 自动云同步或远程数据库；
- 服务端搜索、服务端向量库、消息队列；
- 以 WebView/Capacitor 壳替代原生 Android；
- 只有按钮或文案、没有真实行为和失败反馈的占位功能。

## 2. 架构与数据归属

```text
backend/app/                           FastAPI 路由、服务与 SQLAlchemy 模型
backend/storage/                       Web 本地数据库与文件资产（不入 Git）
frontend/src/                          React 页面、组件、状态与 API 客户端
android/app/src/main/java/com/mojing/  Android UI、ViewModel、Room 与系统能力
android/app/src/test/                  Android JVM 单元测试
android/app/src/androidTest/           Android 设备/模拟器测试
data/                                  内置资源与显式迁移输入
scripts/                               本机启停、迁移和诊断
```

| 数据 | Web | Android | 约束 |
|---|---|---|---|
| 会话、消息、分支 | FastAPI + SQLite | Room | 各端本地保存，不按账号分区 |
| 角色、百科、模板 | SQLite + 文件 | Room + 应用文件 | 导入后可检索，删除处理关联 |
| API Key/供应商配置 | 本机配置/数据库 | 加密偏好与本地数据库 | 不写日志、文档或普通导出 |
| 图片、音频、附件 | `backend/storage/` | 应用私有目录/授权 URI | 丢失引用必须可见并可恢复 |
| 备份与交换包 | 本地导出 | 本地导出 | 恢复前校验，失败不破坏原数据 |

Web 与 Android 共享产品语义和交换格式，但不共享同一个运行时数据库。跨端连续性依赖明确的导入/导出流程，不得暗示自动同步。

Web 世界模板与 Lore 可通过本机 API 导出，与模型供应商配置无关。v1 世界包导入先校验完整内容与冲突，再统一提交数据和成功记录；失败回滚旧资料。替换自定义模板时保留同标识模板的数据库 ID，内置模板不可覆盖。此规则不代表其他交换格式已全部完成同等验收。

Web 世界生成和文本整理的完整结果保留在原任务记录，支持刷新找回、摘要分页、按需详情和保存到世界库。记录原文与玩家之后修改的模板相互独立；保存结果不覆盖已存在的同标识世界，重复请求只保存一份。生成使用可取消的异步调用，离页前可继续或停止；草稿保存在当前浏览器中。新任务保存 v1 输入与分步检查点，支持步骤完成后暂停、失败续跑及执行所有者退出后的中断恢复；旧记录缺失的输入和进度不能追溯补回。

角色资料转移：Web 角色库可直接导入 PNG/JSON 角色卡、便携包或 PNG 文件链接；新增角色按收藏优先、创建时间倒序排列，导入结果可直接定位，当前编辑不会被覆盖。便携角色与详细资料原子写入，TXT/DOCX 便携格式保留详细资料和段落。

Web 世界创作的新任务支持检查点暂停与续跑：当前步骤保存后暂停，生成记录可在重进后继续，已完成步骤不重复执行。异常退出且执行所有者已结束时可恢复；旧记录缺少输入与中间结果时无法补回。

## 3. 核心用户闭环

### 首次使用

1. 启动后直接进入本地应用；
2. 未配置模型时提供清晰的设置入口和错误说明；
3. 配置完成后可创建角色、世界和会话；
4. 初始化失败时展示重试或修复入口，不停在空白页。

新内置目录为“雾港来信”：一个百科、一个世界、沈照与林汐两名角色。Web 创作中心可直接创建带有完整配套资料的对话；两端使用一致内容。Web 只安装一次；旧版原样且无已知引用的示例从默认列表收起，原始行保留且可显式恢复。已修改、使用或配置引用的旧资料不会被收起，也不会在启动时被旧种子程序覆盖。

### 对话与剧情

```text
创建会话
→ 选择角色与世界设定
→ 发送消息
→ 流式显示回复
→ 停止、重试、编辑或分支
→ 搜索、定位与继续创作
→ 导出或备份
```

关键规则：

- 发送、停止、重试、分支切换和重生成由单一生成 owner 串行管理；
- 流式回复区分临时状态与已提交消息，失败不能留下半条或写错会话；
- 编辑消息采用非破坏性分支语义，原消息和原后续剧情保留；
- 当前分支决定消息窗口、搜索、上下文、长期记忆、导出和回复落点；
- Web 单条删除保护故事线/检查点来源及编辑版本，普通消息先确认再删除；创建与删除在同一 SQLite 写入序列内校验来源。删除旧消息优先保持附近阅读位置，不删除媒体文件；
- Android 撤回先展示影响并确认，Room 事务重新检查故事线/检查点和跨线编辑引用，成功后保持附近历史。保留既有同线回复版本回退；仅连带撤回有 v1 生成标记的同线子媒体，旧无标记和普通排除消息保留。沿用既有收藏/自动记忆更新及未被引用的私有媒体清理，设备交互仍需验收；
- 草稿按会话隔离，确认用户消息落库后才清理相同草稿；
- 动态选项与剧情正文分离，未选择选项不进入后续上下文或摘要；
- 角色、百科、世界模板和会话绑定的写入必须具备完整失败反馈。

### 角色、百科与世界

Android 当前内置“雾港来信”一套配套内容：一个百科、一个世界、两个角色。旧目录仅在原样且未使用时归档替换；有用户修改或引用的目录保留。示例只初始化一次。角色在全部/百科筛选中均按置顶、收藏、创建时间排列。

Android 生成记录集中展示分类、进度、错误详情与结果入口；暂停在当前保存步骤结束后生效并记住状态，失败从已保存进度继续。条目/时间线和进度同事务落库，取消状态不被晚到完成覆盖。

- 角色可独立配置模型线路，也可继承公共线路；
- 百科、WorldInfo 和世界模板支持导入、编辑、检索和会话绑定；
- 智能生成结果必须先展示和校验，再以事务或等价原子边界保存；
- 删除角色、词条、模板或媒体时要处理关联，不自动删除用途不明文件；
- 导入必须先完整解析与验证，再写入正式数据。

## 4. 长历史与上下文

“几十万至上百万上下文”指单个会话累计保存大量历史后，仍能流畅打开、分页、滚动、搜索、编辑、定位和继续对话；不代表每轮把全部历史常驻内存、一次性渲染或全部发送给模型。

必须分开处理：

1. 原始消息永久保存；
2. 稳定 ID 的 keyset/cursor 分页；
3. 有界可见窗口与虚拟化；
4. 本地增量全文索引；
5. 搜索结果跳转到未加载消息；
6. 单轮模型上下文预算；
7. 摘要、长期记忆与来源；
8. 编辑、删除和分支后的增量失效；
9. 崩溃恢复；
10. 索引/缓存版本与重建。

禁止用全量读取、Offset 深分页、全量 DOM/View、每次重建索引或完整历史 Prompt 掩盖设计缺陷。

Web 当前故事线搜索使用本机 FTS5 的单字/双字索引与原文子串复核，沿用分支可见性，结果按稳定消息 ID 分页。旧历史每批最多回查 200 条，新增/编辑/删除事务记录变化后每批处理最多 200 条；前端显示整理状态，可暂停、继续、重建并定位未加载原文。派生索引可重建，不改变原始消息及 Web/Android 交换格式。Android 原生搜索另行维护。

## 5. 上下文与长期记忆

原始消息是最高可信来源，自动摘要不得覆盖原文。单轮上下文按预算组合：

1. 核心系统规则；
2. 当前角色和用户人格；
3. 场景与必要世界设定；
4. 最近原文；
5. 相关旧剧情、长期事实和摘要；
6. 用户锁定内容；
7. 当前消息。

冲突时优先用户锁定/纠正、当前分支最新事实、固定设定、世界规则、有原文来源的记忆、自动摘要，最后才是模型推测。自动记忆必须记录来源与分支，并能在消息编辑、删除或分支变化后失效或重建。

## 6. 数据完整性

Web 删除原文或切换上下文参与状态时，回退当前原文分支的受影响自动摘要及后续进度，移除对应范围的自动事件，主线自动概览重新整理；锁定纠正与角色状态保留。v2 后台摘要在落库前从此前进度重新验证有界来源页，拒绝过期结果。消息菜单提供排除/恢复入口、状态标记和失败恢复，排除不删除原文，不影响历史搜索。Android 对应上下文操作、旧无来源事件和旧角色状态的完整失效仍待验收。

不可随意重建的数据包括原始消息、编辑版本、分支、角色、人格、世界书、用户设置、手动记忆、媒体、收藏和用户校正。索引、缓存、自动摘要、缩略图和 Token 缓存属于派生数据，可在不改写原始数据的前提下重建。

任何 schema 或交换格式变化必须包含：

- 明确的数据版本；
- 升级前校验；
- 幂等迁移；
- 失败恢复或回滚方式；
- 旧样本、重复迁移和大型数据测试；
- Web/Android 兼容影响。

不得通过删除旧数据库解决升级问题。恢复或覆盖导入必须先校验，失败不能先破坏正式数据。

## 7. 安全与隐私边界

MoJing 默认运行在用户自有设备上，本机 API 绑定回环地址。当前威胁模型不包含公网多用户托管。

- `.env`、密钥、数据库、媒体和本机配置禁止进入 Git；
- 日志、异常、测试快照和普通导出不得包含完整密钥或认证头；
- 若主动开放局域网/公网访问，部署者必须自行增加 TLS、鉴权、防火墙和访问范围控制；
- 不为了理论安全引入会阻碍用户读取和迁移自己数据的复杂企业级方案。

## 8. UX 与跨端语义

所有可见入口至少要有真实动作或不可用原因，并按需要提供加载、空、错误、重试、取消和返回状态。

Web 重点：窄屏、深链/刷新、前进后退、虚拟列表、流式贴底、草稿恢复、请求取消和局部失败恢复。

Android 重点：系统/手势返回、IME 与 Insets、旋转/分屏/进程重建、权限与文件错误、小屏和字体放大。

两端不要求共享 UI 代码，但必须共享会话、消息、分支、角色、世界书、上下文顺序、错误语义和导入导出版本。

## 9. 验证边界

必须区分以下证据：

- 静态源码/配置；
- 自动测试；
- Web/Android 构建；
- 日志或 telemetry；
- 浏览器真实运行；
- 模拟器运行；
- 真机运行；
- 大型数据和性能测试；
- 用户报告。

测试或构建通过不能冒充真实用户流程已验证；模拟器不能冒充真机；用户报告不能冒充独立复现。

## 10. 当前已知边界

- Web 与 Android 不自动同步；
- 第三方模型、图片和语音协议可能变化，需要探活与错误回归；
- 大型历史性能仍需在真实设备、真实浏览器和代表性数据集上持续验证；
- IME、系统返回、权限、文件选择器和媒体保存需要真机矩阵；
- Android 改用 `com.mojing.app` 后，早期预改名应用需要通过显式导出/导入迁移数据。

当前优先级与未闭环事项见仓库根目录的 [`docs/PRODUCT_GAP_MAP.md`](../docs/PRODUCT_GAP_MAP.md)。
